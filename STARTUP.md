# T-Echo Monitor — Инструкция по установке

## Мониторинг и управление Meshtastic сетью 433 МГц (прошивка 2.7.15)

> **MQTT не используется** — подключение только через USB (serial), удалённый мониторинг через интернет не нужен.

## Быстрый старт (5 минут)

### 1. Установите Bun

**Windows (PowerShell):**
```powershell
powershell -c "irm bun.sh/install.ps1 | iex"
```

**macOS / Linux:**
```bash
curl -fsSL https://bun.sh/install | bash
```

> Альтернатива: можно использовать **Node.js 20+** вместо Bun.
> Скачайте с https://nodejs.org → кнопка «LTS»

### 2. Клонируйте репозиторий

git clone https://github.com/Pronin2010/techo-monitor.git
cd techo-monitor

### 3. Откройте терминал в папке проекта

**Windows:** Откройте папку → нажмите `Ctrl+L` → введите `cmd` → Enter

**macOS:** Откройте Terminal → перетащите папку в окно терминала

**Linux:** Правый клик в папке → «Открыть терминал»

### 4. Запустите команды

```bash
# Установите зависимости (1-2 минуты)
bun install

# Создайте базу данных
bun run db:push

# Запустите сервер
bun run dev
```

### 5. Откройте в браузере

```
http://localhost:3000
```

Вы увидите дашборд для мониторинга Meshtastic-сети.

## Структура дашборда

### Вкладка «Статус»
- Карточки всех устройств: батарея, сигнал (SNR/RSSI), роль, режим сна
- **Расширенная телеметрия** (в аккордеоне): скорость (км/ч), курс (°), кол-во спутников GPS, HDOP (точность), давление (гПа), загрузка канала (%), эфир TX (%)
- Роли: ROUTER (ядро сети), TRACKER (GPS-трекер), CLIENT, SENSOR, CLIENT_BASE, ROUTER_LATE, TAK_TRACKER
- Устаревшие роли: REPEATER, ROUTER_CLIENT (не рекомендуются в 2.7.x)
- Индикаторы: бодрствует/спит, ретранслирует/только свои

### Вкладка «Карта»
- Позиции устройств на карте (Leaflet/OpenStreetMap)
- Маркеры с цветами по ролям
- Линии связи между узлами
- В попапе маркера: скорость, курс, кол-во спутников

### Вкладка «Каналы»
- Настройки каналов: PSK-ключи 256 бит, модем-пресет, регион (только 433 МГц)
- QR-коды для быстрого подключения трекеров
- Uplink/Downlink настройки

### Вкладка «Подключение»
- Настройка Serial/MQTT подключения
- Скрипт techo-bridge.py для связи с устройствами

### Вкладка «Настройка»
- Генерация CLI команд и YAML конфигов для meshtastic 2.7.15
- Все роли, пресеты, регионы актуальны для прошивки 2.7.15

### Вкладка «Пресеты»
- Компактные карточки в стиле устройств — адаптивная сетка встроенных системных пресетов
- Встроенные пресеты: трекер (TRACKER + LONG_MODERATE + GPS), базовая станция (ROUTER + LONG_MODERATE), клиент (CLIENT + LONG_FAST)
- Создание собственных пресетов с произвольными параметрами
- Генерация CLI-команд и YAML-конфигов для применения пресета к устройству
- **Отправка конфигурации на устройство** — кнопка загрузки (зелёная стрелка) применяет пресет через мост напрямую на устройство
  - Установка имени (long name) и короткого имени (short name, макс. 5 символов) при отправке
  - Имя автозаполняется из текущего устройства, можно изменить или оставить пустым
  - Опция «Сбросить до заводских» — удаляет все настройки перед применением пресета (рекомендуется для новых устройств)
    - Сначала вызывается ensureSessionKey() для получения session_passkey, затем AdminMessage.factory_reset_config=1
    - Без session_passkey устройство молча игнорирует admin-команды
    - При сбросе мост автоматически пересоздаёт SerialInterface (5 попыток с задержкой)
    - Ожидание перезагрузки: 20 сек (устройство полностью перезагружается)
  - Применение канала (PSK, имя, uplink/downlink) из привязанного канала пресета
  - Транзакционное применение: при ошибке — автоматический откат через перезагрузку (без частичных изменений)
  - nodeId устройств в hex-формате `!a1b2c3d4` (для корректной удалённой отправки)

### Вкладка «Пакеты»
- Мониторинг потока пакетов в реальном времени
- Отображение входящих/исходящих пакетов с метаданными
- Автообновление при поступлении новых данных от устройств

## Подключение реальных T-Echo

### Способ 1: Через USB (рекомендуется)

1. Подключите Base Station (ROUTER) к компьютеру по USB
2. Установите Python-зависимости:
   ```bash
   pip install meshtastic requests
   ```
3. Запустите скрипт-мост:
   ```bash
   python techo-bridge.py --mode serial --port /dev/ttyUSB0 --dashboard http://localhost:3000
   ```
   - Linux: `/dev/ttyUSB0`
   - macOS: `/dev/cu.usbmodem*`
   - Windows: `COM3` (проверьте в Диспетчере устройств)
   - Мост автоматически запускает HTTP API на порту **8420** для приёма команд от дашборда
   - `GET /api/device-config` — чтение текущей конфигурации устройства (для диагностики)

4. Скрипт чтения конфигурации:
   ```bash
   # Прочитать и вывести все настройки устройства
   python techo-dump-config.py --port COM5

   # Сохранить в JSON файл
   python techo-dump-config.py --port COM5 --output device-config.json
   ```

4. Скрипт автоматически обнаружит все устройства в mesh-сети
5. Для чтения текущей конфигурации используйте `techo-dump-config.py` (см. ниже)

### Способ 2: Через MQTT (не используется)

> MQTT не применяется в данном проекте. Подключение только через USB (serial).

```bash
# Для справки — не рекомендуется к использованию
python techo-bridge.py --mode mqtt --broker mqtt.meshtastic.org:1883 --topic msh/EU_433/# --dashboard http://localhost:3000
```

## Настройка нового T-Echo

### Быстрая настройка (через компьютер):

```bash
# Установите регион 433 МГц
python -m meshtastic --set lora.region EU_433

# Установите роль
python -m meshtastic --set device.role ROUTER    # для Base Station
python -m meshtastic --set device.role TRACKER    # для трекера

# Настройте интервал сна (для трекеров)
python -m meshtastic --set power.ls_secs 300      # 5 минут
python -m meshtastic --set power.ls_secs 2700     # 45 минут

# Включите GPS (через gps_mode вместо устаревшего gps_enabled)
python -m meshtastic --set position.gps_mode ENABLED
python -m meshtastic --set position.gps_update_interval 30

# Создайте приватный канал с PSK 256 бит
python -m meshtastic --ch-index 0 --ch-set psk "base64:<ВАШ_КЛЮЧ>"
python -m meshtastic --ch-index 0 --ch-set name "forest-track"
```

### Быстрая настройка (через телефон):
1. Скачайте приложение **Meshtastic** (Android/iOS)
2. Подключитесь к T-Echo по Bluetooth
3. Device Settings → LoRa → Region → **EU_433**
4. Device Settings → Device Role → **ROUTER** / **TRACKER**
5. Channel Settings → «+ New channel» → Private → название: `forest-track`

## Рекомендуемая конфигурация для леса

| Устройство | Роль | Интервал сна | Модем | Примечание |
|------------|------|-------------|-------|------------|
| Base Station | ROUTER | Не спит | LONG_MODERATE | Подключён к ПК по USB |
| Tracker Alpha | TRACKER | 5 мин (300 сек) | LONG_MODERATE | В лесу |
| Tracker Bravo | TRACKER | 45 мин (2700 сек) | LONG_MODERATE | В лесу |

**Разные интервалы сна** на трекерах = выше шанс, что хотя бы один бодрствует.

## Важные изменения в прошивке 2.7.15

| Изменение | Влияние |
|-----------|---------|
| **Телеметрия отключена по умолчанию** | Нужно явно включать через приложение или CLI |
| **Прямые сообщения только через PKI** | Шифрование по умолчанию для личных сообщений |
| **Traffic Management включён по умолчанию** | Позиции дедуплицируются, rate limiting активен |
| **`gps_enabled` устарело** | Используйте `position.gps_mode ENABLED/DISABLED` |
| **`REPEATER` и `ROUTER_CLIENT` устарели** | Не рекомендуются к использованию |
| **Новые роли**: TAK_TRACKER, ROUTER_LATE, CLIENT_BASE | Расширенные возможности маршрутизации |
| **Новые пресеты**: LITE_FAST/SLOW, NARROW_FAST/SLOW | Для узкополосных режимов |
| **session_passkey обязателен** | Без ensureSessionKey() устройство молча игнорирует admin-команды |
| **BT PairingMode: RANDOM_PIN=0, FIXED_PIN=1** | FIXED_PIN = 1, НЕ 0! (проверено по protobuf config.proto) |

### Точность координат (position_precision)

**Важно**: `position_precision` — это настройка **КАНАЛА**, а не позиции!
Устанавливается через `--ch-set`, а не `--set`.

```bash
# Максимальная точность (~1м) — для трекеров
meshtastic --ch-index 0 --ch-set module_settings.position_precision 32

# Не передавать координаты — для базовой станции
meshtastic --ch-index 0 --ch-set module_settings.position_precision 0
```

| Значение | Радиус | Описание |
|----------|--------|----------|
| 0 | — | Не передавать позицию |
| 13 | ~2.9 км | Дефолт прошивки |
| 32 | ~1-3 м | Максимальная точность (GPS) |

⚠️ НЕ используйте `--set position.position_precision` — это не работает в 2.7.x!

### Флаги позиции (position_flags)

Битовая маска, определяющая какие данные включать в позиционный пакет:

| Флаг | Значение | Описание |
|------|----------|----------|
| ALTITUDE | 1 | Высота |
| ALTITUDE_MSL | 2 | Высота MSL (иначе HAE) |
| GEOIDAL_SEPARATION | 4 | Геоидальное отделение |
| DOP | 8 | DOP (PDOP) |
| HVDOP | 16 | HDOP/VDOP вместо PDOP |
| SATINVIEW | 32 | Кол-во спутников |
| SEQ_NO | 64 | Номер пакета |
| TIMESTAMP | 128 | Метка времени GPS |
| HEADING | 256 | Направление (транспорт!) |
| SPEED | 512 | Скорость (транспорт!) |

```bash
# Пеший режим (дефолт в пресетах) — без SPEED
meshtastic --set position.position_flags 299

# Транспорт (дефолт прошивки) — со SPEED
meshtastic --set position.position_flags 811
```

### ⚠️ Известные проблемы nRF52840 (T-Echo) в прошивке 2.7.x

| Проблема | GitHub Issue | Описание |
|----------|-------------|----------|
| BT FIXED_PIN не работает | #9812 | На nRF52 без экрана NimBLE ставит IO capability NoInputNoOutput → конфликт с MITM |
| Перезагрузка при BT-сопряжении | #7103 | nRF52840 может перезагружаться при BT-подключении в прошивке 2.7.x |

> **Примечание**: T-Echo имеет экран, поэтому проблема #9812 может не проявляться. Если FIXED_PIN не работает, используйте RANDOM_PIN (безопаснее) или NO_PIN.

## Частые проблемы

### «Не удалось загрузить данные»
- Проверьте, что сервер запущен: `bun run dev`
- БД обновляется автоматически при запуске (prisma db push)
- Если ошибка «Unknown argument» — обновите БД вручную: `bun run db:push`
- Проверьте, что файл БД существует: `db/custom.db` (путь в .env: `file:../db/custom.db`)

### «Устройство не видно по USB»
- Linux: `ls /dev/ttyUSB*` — если пусто, проверьте кабель и драйверы
- macOS: `ls /dev/cu.usbmodem*`
- Windows: Диспетчер устройств → Порты COM
- Попробуйте другой USB-кабель (нужен кабель с передачей данных!)

### «Не вижу другие узлы»
- Убедитесь, что **регион одинаковый** на всех устройствах (EU_433)
- Убедитесь, что **канал и PSK одинаковые**
- Проверьте, что антенна подключена
